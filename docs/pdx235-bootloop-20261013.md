# pdx235 candidate boot failure, October 13

The rootless October 9 candidate exported by ModOS commit `b8b2a1e`
(run [38318273364](https://github.com/0cwa/ModOS/actions/runs/38318273364))
failed to start Android on the physical Xperia 10 V. Private ADB logs from
slot B identify the failure:

```text
SELinux: seapp_contexts: Duplicated entry
SELinux: user=_app
SELinux: name=com.chiller3.msd
SELinux: partition=vendor
SELinux: seapp_context_lookup_internal: No match for app with uid 1000
zygote64: JNI FatalError called: (system_server) ... selinux_android_setcontext ... failed
```

The boot reported `reboot,zycold-fatal`, a locked bootloader, yellow verified
boot, and enforcing verity. These observations identify an app-context parsing
failure; they do not establish complete care-map or snapshot acceptance.
The phone subsequently booted the previous July 24 installation on slot A;
ADB observed `sys.boot_completed=1`, and the owner unlocked Android. No agent
flashing, slot changes, data wipe, or verification changes were performed.

The candidate helper `cf613de0494374bef2face58fd2bb00cc0b1dca2` copied
Custota and MSD platform app-context rules into both vendor and ODM files in
compatible mode. Android loads both with vendor precedence and rejects their
duplicate selectors. The helper correction appends module app-label rules once
in `plat_seapp_contexts`. Binary and CIL policy patching remain enabled.

The focused regression now checks that module selectors appear once across the
context files and that vendor/ODM app-context files remain unchanged while CIL
patches still reach their partition roots. It failed on the original helper
and passes after the correction. The development helper pin includes this fix;
production pins and publication quarantine remain unchanged.

The original candidate must not be reinstalled. Cryptographic and filesystem
inspection of the original outputs did not catch this Android parser constraint.
A corrected repository-signed candidate requires fresh output verification,
physical first boot, and successful-slot/OTA persistence observations before
acceptance. The previous slot remains the recovery option; do not wipe userdata
or disable verity to work around this failure.

The first repaired-helper build, run `38389845277`, passed artifact checks but
selected the provider's latest source: LineageOS 24.0, October 12, SDK 37.
It was not installed. The development source is now fixed to the original
October 9 filename and digest in the official API; missing or changed fixtures
are rejected. Ordinary production provider selection remains unchanged.
